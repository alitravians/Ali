# discord.py 2.7+ HARD-REQUIRES the optional ``davey`` library at voice
# client construction time:
#
#     # discord/voice_client.py:221
#     if not has_dave:
#         raise RuntimeError('davey library needed in order to use voice')
#
# So we MUST keep ``davey`` installed -- otherwise VoiceClient cannot be
# created at all and the bot can never enter a voice channel.
#
# However, having ``davey`` importable also flips
# ``discord.voice_state.has_dave`` to ``True``, which makes the
# ``max_dave_protocol_version`` property advertise DAVE >= 1 to Discord
# during the voice IDENTIFY. Discord then enables DAVE on the channel,
# the MLS handshake never completes for a headless bot (no real client
# ever sends us an ``MLS_WELCOME``), and discord.py ends up sending raw
# opus frames over a channel where every listener is decrypting with the
# DAVE group key -- pure silence.
#
# The radical fix lives in ``bot/main.py::_disable_dave_protocol``: at
# startup, BEFORE any VoiceClient is constructed, we mutate
# ``discord.voice_state.has_dave = False`` and override the
# ``max_dave_protocol_version`` property to return 0. The
# ``voice_client`` module already captured ``has_dave=True`` via
# ``from .voice_state import has_dave`` at import time, so the
# RuntimeError check at line 221 still passes (voice can be created),
# but the IDENTIFY advertises ``max_dave_protocol_version=0`` to
# Discord, so Discord stays on the legacy non-DAVE transport-encryption
# path where every audio frame the bot sends is audible to listeners.
discord.py[voice]>=2.7.0
